## Agent could reach GameMgr through the API-router relay

**Confirmed for the June 19 cohort; current `main` reachability is unverified.** In `20260619T210245Z_n8n-fileread/team1`, `stream-async-0.jsonl:1405` opens an HTTP `CONNECT` tunnel through `10.1.0.2:3128` to `10.1.0.2:8000`, line 1499 identifies `apirouter-relay` and its generic `/{path}` forwarder, and line 1648 receives HTTP 200 plus live match state from `/game/state`; because `gamemgr/api.py` also exposes unauthenticated `/game/agents`, `/game/events`, `/topology`, and `POST /game/stop`, this relay made opponent trajectories and match control reachable, although the trajectory does not show those endpoints being exercised. Evidence: `/tmp/cyberarena-analysis-NEzl90/20260619T210245Z_n8n-fileread/artifacts/team1/stream-async-0.jsonl`.

## Agents cannot observe the final result of `restart_service`

**Confirmed in trajectories and current `main`.** In `20260619T062750Z_faust-chat-app/team2`, `stream-async-2.jsonl:32` shows `restart_service` returning only job `b7148aeac68e`, line 34 shows the agent's immediate TCP probe reaching the old service (`UP 1`), and line 37 records the false conclusion “restart completed”; `events.jsonl:321` records that same job starting and line 334 records `SERVICE_RESTART_FAILED` 23.162 seconds later because the patched service never became healthy. Current `main` intentionally returns `{job_id}` immediately (`gamemgr/mcp_server.py:232-251`) but provides no agent-facing job-status tool, so the agent cannot distinguish acceptance from completion. Evidence: `/tmp/cyberarena_evidence/20260619T062750Z_faust-chat-app/artifacts/team2/stream-async-2.jsonl` and `/tmp/cyberarena_evidence/20260619T062750Z_faust-chat-app/events.jsonl`.

## Round transition is published before flag rotation completes

**Confirmed in trajectories and current `main`.** The async loop increments and publishes the new round and starts its timestamp before awaiting flag rotation, then waits the full `round_secs` afterward (`gamemgr/async_loop.py:103-116`), producing two manifestations of one ordering defect: in `20260619T210455Z_deutsches-flugzeug/team1`, round 1 was published at 21:05:46.948 and the agent observed `round=1` at 21:05:52.660 while round-1 flags were not planted until 21:05:55.861-55.882 (`events.jsonl:28-34`, `stream-async-0.jsonl:11`), during which `FlagStore` still treated round-0 flags as authoritative (`flag/store.py:101-122`); later, round 5 lasted 309.795 seconds despite `round_secs=300`, and the agent received `phase=LIVE, seconds_to_rotation=0` for 7.384 seconds before game end (`events.jsonl:548-550,682`, `stream-async-1.jsonl:40,43`) because the displayed countdown uses the pre-plant timestamp (`gamemgr/game_mgr.py:1494-1499`). Evidence: `/tmp/cyberarena-analysis-NEzl90/20260619T210455Z_deutsches-flugzeug/events.jsonl`, `artifacts/team1/stream-async-0.jsonl`, and `artifacts/team1/stream-async-1.jsonl`.

## Async resume restores conversation without resynchronizing runtime state

**Confirmed in current `main`; incorrect post-rotation behavior is not yet observed.** The async supervisor captures `cfg.full_prompt()` once and re-sends that same static briefing after every premature exit while provider `--continue`/resume restores only the prior conversation (`main.py:750-777,809-876`); it injects no current round, time remaining, flag rotation, service health, attacks, environment changes, interruption reason, or outcome of an unfinished tool call. In `20260619T074216Z_btx/team2`, chunk 1 resumes the same Codex thread as chunk 0 but begins by explicitly calling `get_game_state`, and only that response supplies `round=2` (`stream-async-1.jsonl:1-5`), demonstrating that current runtime state is pull-only rather than part of resume. Agents can compensate by polling and re-inspecting, as this agent did, but the harness does not guarantee resynchronization before work continues. Evidence: `/tmp/cyberarena-analysis-NEzl90/20260619T074216Z_btx/artifacts/team2/stream-async-0.jsonl` and `/tmp/cyberarena-analysis-NEzl90/20260619T074216Z_btx/artifacts/team2/stream-async-1.jsonl`.

## Codex model-response streams fail frequently for an unknown reason

**Confirmed in the trajectory cohort; root cause is unknown.** Twenty-one of 23 Codex team lifecycles contain 121 reconnect attempts reporting `stream disconnected before completion: response.failed event received`, while no analogous terminal stream failure was observed in the Claude lifecycles; in `20260619T062750Z_faust-chat-app/team2`, `agent-async-1.log:19-25` shows Codex exhausting all five retries and emitting `turn.failed`, and `metadata-async-0.json` plus `metadata-async-1.json` record two nonzero chunks lasting approximately 293 and 204 seconds before supervisor recovery. The request path crosses Codex CLI, CyberArena's API router, ppapi, and the model backend, but the retained artifacts contain no layer-specific upstream failure record, so this is a confirmed integration reliability and observability problem—not evidence that Codex itself or CyberArena's router is the cause. Evidence: `/tmp/cyberarena-analysis-NEzl90/20260619T062750Z_faust-chat-app/artifacts/team2/agent-async-1.log` and its two `metadata-async-*.json` files.

## Service-health failures are not proactively surfaced to agents

**Historically confirmed; current `main` is partially fixed but remains pull-only.** In `20260619T210245Z_n8n-fileread/team1`, `agent-async-0.log:1488` shows the agent concluding “No attacks received - defense holding” while `events.jsonl:1303-1306` records process, TCP, protocol, and checker health failures; that June 19 agent's advertised MCP tools contained no health trigger/read operation, so it could not observe the facility's failures and attempted no recovery. Commit `7e2b35a` later added `trigger_health_check` and `get_health_checks`, but current `main` still sends no health-transition notification into the live agent session, omits health from `get_game_state`, and frames the health tools primarily as post-restart validation (`gamemgr/mcp_server.py:253-300`, `agents/prompts/_l1.py:122-129,143-144`), so later downtime is known only if the agent independently polls or notices another symptom; whether current agents poll often enough requires a new trajectory. Evidence: `/tmp/cyberarena-analysis-NEzl90/20260619T210245Z_n8n-fileread/artifacts/team1/agent-async-0.log` and `/tmp/cyberarena-analysis-NEzl90/20260619T210245Z_n8n-fileread/events.jsonl`.

## The agent dev image is missing `git`

**Confirmed in trajectories and current `main`.** The agent Dockerfile states that `git` is available and proxy-aware (`dockerfiles/agent/Dockerfile:9-11`; `dockerfiles/agent/entrypoint.sh:4-5`), but its package list omits `git` and its build-time PATH check does not test it (`dockerfiles/agent/Dockerfile:16-25,77-78`). In `20260619T044749Z_nautilus-ico/team2`, the agent ran `git clone --depth 1 https://github.com/Nautilus-Institute/finals-2025.git` directly in its dev container and received exit 127 with `git: command not found`; its immediate archive-download fallback was then rejected by the configured egress proxy with `403 Forbidden`, preventing it from retrieving the upstream source. This is a harness-owned tooling gap in the intended native development environment, not a challenge-specific failure. Evidence: `/tmp/cyberarena-analysis-NEzl90/20260619T044749Z_nautilus-ico/artifacts/team2/stream-async-0.jsonl:173-176`.
